# Calendar

DayPicker calendar with Foglamp button styling and a dedicated day button. The wrapper exposes DayPicker props plus a Button-compatible buttonVariant.

## API and props

The table lists values exported from `@tailrocks/framerock/ui/calendar`. The declared type comes from the component source.

| Export | Declared props or type | Role |
| --- | --- | --- |
| `Calendar` | `React.ComponentProps<typeof DayPicker> & { buttonVariant?: React.ComponentProps<typeof Button>["variant"]; }` | Calendar root backed by DayPicker. |
| `CalendarDayButton` | `React.ComponentProps<typeof DayButton> & { locale?: Partial<Locale> }` | Interactive calendar day. |

## Additional props

| Prop | Type | Description |
| --- | --- | --- |
| `Calendar.buttonVariant` | `Button variant` | Variant used by day buttons. Defaults to `ghost`. |

## Example

The example is the portal story fixture without its story registration. It uses the same package imports as the live preview.

```tsx
import { useState } from 'react';

import { Calendar } from '@tailrocks/framerock/ui/calendar';

function CalendarExample({ month = 10 }: { month?: number }) { const [date, setDate] = useState<Date | undefined>(new Date(2026, month, 5)); return <Calendar mode="single" selected={date} onSelect={setDate} className="rounded-md" />; }
```

## Registry item

The story panel resolves this component as registry item `ui-calendar`. When the portal runs locally at `http://localhost:3000`, the JSON URL is `http://localhost:3000/r/ui-calendar.json`. The matching local install command is `npx shadcn@latest add http://localhost:3000/r/ui-calendar.json`. This URL is local to the running portal, not a public registry address.

The package import path is `@tailrocks/framerock/ui/calendar`. The workspace declares `@tailrocks/framerock` as a package; these docs do not claim npm publication.
